# 垃圾文件清理 2.0.0（SDK1）

需要 **Kanojo >=1.2.1,<2**。本插件继承 SDK 的 `BasePlugin`，使用类型化设置、独立数据目录、托管任务、进度、取消与标准分页界面。无需 qBittorrent 或任何外部服务能力。目录句柄保护使用 POSIX 接口，适用于 Linux 容器及 Linux/macOS 源码运行环境。

## 使用

1. 在「清理设置」填写服务端可访问的默认扫描路径和清理关键词，每行一个。关键词也支持中英文逗号分隔，按文件名匹配，不区分大小写。
2. 保存设置后点击「开始扫描」。临时扫描路径留空使用默认目录，填写时只扫描该临时目录。
3. 查看「候选文件」，按文件大小从大到小排列，每页 30 项。
4. 勾选本页需要清理的文件，点击「删除所选」，确认后执行。扫描和删除的任务进度与取消按钮都在插件界面中。

插件没有定时清理，不会在启用、重启、配置保存或扫描时自动删除。关键词留空时不能清理，也不会读取主程序或下载器的过滤关键词。删除只针对文件，不删除文件夹。

## 删除检查

服务端根据扫描记录识别所选文件，删除请求只接受候选 ID。临时路径的授权来自那次完成的扫描。每项操作前检查设置版本，核对文件名、扫描目录、文件类型、设备与 inode、大小、修改时间和状态变更时间；发生变化则跳过，并在候选表格中显示原因。目录遍历和删除使用不跟随符号链接的目录句柄，扫描也跳过符号链接。

修改设置或完成新扫描后，旧选择失效，需要重新核对。清理任务在进程重启或插件重载后不会自动继续删除：旧代次的排队请求也会被拒绝，需要再次手动确认。取消后已经删除的文件不会恢复，剩余文件继续保留。

扫描最多检查 200000 个目录项、保存 2000 个候选文件；单目录最多读取 100000 项。达到限制或部分目录读取失败会显示在任务消息中，可缩小路径重新扫描。扫描只读取目录项和文件属性，不打开文件内容。取消扫描时保留上一次完整结果。

## 从 Legacy 1.2.0 升级

通过宿主的正常插件更新流程，会把旧 `config.json` 中的 `scan_paths` 和 `keywords` 迁移到 SDK1 的独立设置目录，兼容旧文本或数组格式并去重。未设置过的关键词仍为空，不代入 qBittorrent 的过滤词。迁移不会扫描或删除文件；若迁移或新插件加载失败，宿主恢复旧代码与配置。

开发模式使用独立开发数据，不会导入正式版配置。在「插件 → 插件开发」添加本目录即可预览；扫描和删除检查请使用自己的测试目录。

## 打包与发布

```bash
PYTHONPATH=/path/to/kanojo/backend /path/to/kanojo/venv/bin/python tools/package_sdk.py junk-cleaner
```

产物为 `dist/junk-cleaner-2.0.0.zip`、SHA-256 和 `.release.json` 索引条目。上传固定版本 Release 资产后，再把条目合入 `index.v2.json`；旧 `index.json` 继续保留指向 Legacy 1.2.0 的固定提交地址。打包不会自动发布。
